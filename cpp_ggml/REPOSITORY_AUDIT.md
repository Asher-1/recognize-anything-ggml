# Repository Audit (2026-10-08)

This document records the full-tree audit for the GGML integration. A result is
marked as passed only when the corresponding command and artifact exist in this
checkout.

## Integration status

The RAM, RAM++ and Tag2Text inference paths are implemented through the
options-based C++ API and the same GGML graph is exercised by the CLI and the
root `run_inference.py` launcher. GGML is a git submodule pinned to `v0.21.0`
(`8599e0ea3756c4bac4ef813af2241cb1a8bbfb0b`). The integration patch is
consolidated at `third_party/patches/0001-ram-ggml-v0210-integration.patch`
and is applied by CMake. The CUDA and Vulkan builds have no cuDNN dependency.

## Current acceptance evidence

The canonical runs are under `benchmarks/full_eval/`:

| pipeline | evidence | result |
| --- | --- | --- |
| tags | `run-20261008-125945` | 18/18 aggregate combinations and 72/72 dataset rows faster than PyTorch CUDA; minimum cross-engine F1 0.991781; maximum latency ratio 0.923862 |
| Tag2Text caption | `caption-20261008-133340` | 6/6 CUDA/Vulkan and F32/F16/Q8_0 combinations exact on the retained 50 GT frames; exact fraction 1.0, word F1 1.0; maximum latency ratio 0.866826 |

These numbers are tied to the recorded RTX 3060, driver, software versions,
model hashes and the 50-frame GT manifest in `benchmarks/BENCHMARK_METADATA.json`.
They are reproducible release evidence, not a guarantee for an unmeasured GPU,
driver, or a different input distribution.

## Upstream TODOs and legacy notes

The source scan found no unimplemented RAM GGML inference path. Three notes
remain in upstream code and are not hidden by this integration:

| location | meaning | impact |
| --- | --- | --- |
| `ram/models/swin_transformer.py:445` | upstream FIXME about relaxing input-size constraints | current official and C++ contract remains the fixed 384px preprocessing path |
| `README.md` commented release checklist | upstream training-code release item is still unchecked | training is outside the inference integration scope |
| pinned GGML backend comment | upstream scheduler operation has no current use case | no graph generated by this repository requires it |

`unsupported_label_space` is an intentional evaluator result for annotations
whose names are outside the closed 4,585/3,429 class spaces. Dataset-specific
sidecars can be supplied to evaluate those open label spaces; it is not a
missing GGUF tag file.

## Documentation and launcher audit

The model card, benchmark report, release notes and Hugging Face README point
to the current GitHub release and Hugging Face model tree. Their model names,
hashes, Q8_0 sizes and acceptance values were checked against the files in
`models/gguf/` and `BENCHMARK_METADATA.json`.

`run_inference.py` supports both engines, all three models, tags/caption,
CUDA/Vulkan/CPU C++ backends, F32/F16/Q8_0, CUDA compute mode, timing,
preprocessing-included pipeline timing, caption tag constraints, label-space
sidecars, vocabulary fallback, threshold epsilon, automatic export/build and
`--dry-run`. Unsupported Python-only/C++-only options now fail explicitly
instead of being silently ignored. The official Python scripts retain their
upstream device policy (CUDA when available, otherwise CPU); they do not expose
a Vulkan or arbitrary quantization switch.

## Remaining boundaries

The formal acceptance set is the retained 50-frame GT evaluation set. The
repository also preserves the source inventory and selection manifest, but a
50-frame result must not be described as exhaustive evaluation of all 138,873
source rows. The upstream training checklist and the Swin input-size FIXME
remain by design. Any release for another GPU or driver must rerun the matrix
and caption regression before claiming the same latency or exact wording.
