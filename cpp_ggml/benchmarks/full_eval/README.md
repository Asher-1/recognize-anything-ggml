# Full Evaluation Harness

Model downloads: [GitHub RAM release](https://github.com/Asher-1/cloudViewer_downloads/releases/tag/RAM) and
[Hugging Face `Asher-1/RAM_GGUF`](https://huggingface.co/Asher-1/RAM_GGUF/tree/main).

The runnable harness is [`../full_eval.py`](../full_eval.py). It keeps one
absolute image path per manifest row and writes raw JSONL predictions plus a
float32 score matrix for every engine/model/backend/format combination.

## Data Coverage

The repository intentionally retains a 50-frame GT subset under `datasets/`;
the large source corpus was audited first and then pruned. The deterministic
selection, original row counts and per-frame GT labels are recorded in
[`datasets/selection_manifest.json`](../../../datasets/selection_manifest.json)
and [`datasets/SELECTION_REPORT.md`](../../../datasets/SELECTION_REPORT.md):

| Dataset | Source GT rows | Retained GT rows/images | Image directory | Ground-truth protocol |
|---|---:|---:|---|---|
| OpenImages common | 57,224 | 14 | `datasets/openimages_common_214/imgs/test` | `*_ram_annots.txt` and Tag2Text id annotations |
| OpenImages rare | 21,991 | 12 | `datasets/openimages_rare_200/imgs/test` | `*_ram_annots.txt` plus LLM descriptions |
| ImageNet multi | 50,000 | 12 | `datasets/imagenet_multi/imgs` | `imagenet_multi_1000_annots.txt` |
| HICO | 9,658 | 12 | `datasets/hico/imgs` | `hico_600_annots.txt` |
| **Total** | **138,873** | **50** | | |

`python3 ../full_eval.py --scope datasets` performs an existence and count
audit without loading a model and now expects 14, 12, 12 and 12 images. The
ImageNet and HICO source archives were removed after extraction; rerunning
`python3 download_test_data.py all` fetches only the GT rows currently listed
in the annotations and removes temporary archives by default.

To reselect the same deterministic subset after restoring a full source
download, run `python3 select_eval_subset.py` for a dry run and add `--apply`
only after reviewing `datasets/SELECTION_REPORT.md`.

## Retained Dataset Run

Run the complete retained set directly, or use shards if several workers are
needed. A shard loads each model once and keeps the C++ GGML weights resident.

```bash
python3 cpp_ggml/benchmarks/full_eval.py \
  --scope datasets --run \
  --backends cuda vulkan --dtypes f32 f16 q8_0 \
  --batch-size 1 --warmup 1 --repeat 3 --threads 8 \
  --label-space-dir cpp_ggml/benchmarks/label_spaces \
  --output-dir cpp_ggml/benchmarks/full_eval
```

The public 50-frame matrix is in [`../LATENCY_MATRIX.md`](../LATENCY_MATRIX.md).
Run `../latency_matrix.py` with the tag and caption run directories to
regenerate the tracked table, charts and report.

Add `--check-acceptance` to require every requested row's cross-engine F1 to
be at least 0.99 and GGML pipeline latency to be strictly below Python CUDA.
On a shared NVIDIA GPU, use `--wait-gpu-idle` and repeat `--allow-gpu-pid PID`
only for explicitly allowed long-lived services. The harness records compute
PID samples in each command log and retries detected overlap up to
`--gpu-retries` times. `--wait-process-pid PID` waits for another benchmark
coordinator to exit, covering its GPU-idle loading gaps as well.
Resume an interrupted run with `--resume-run DIRECTORY`; with the audit
enabled, only outputs with a successful, overlap-free command log are reused.
Use exactly the same model files, binaries and timing options when resuming.

The standard PyTorch baseline is CUDA when available. GGML raw matrices store
logits; the Python matrices store probabilities, and the report applies the
sigmoid conversion before calculating MAE or mAP. `mAP`, `CP`, and `CR` follow
the official RAM `batch_inference.py` implementation: CP and CR are
class-wise macro averages, including zero-target classes, and duplicate
label names map to every matching column. GT precision/recall use the tags
actually emitted by each engine. Cross-engine F1 is a
separate thresholded tag-set agreement metric.

The retained OpenImages-common companion file supplies Tag2Text GT labels.
The other three datasets only provide RAM/dataset-specific GT labels, so their
Tag2Text `mAP/CP/CR` columns are diagnostic zero-target values; use the
cross-engine MAE/F1 rows for Tag2Text backend parity there.

Every retained row in the four annotation files is a GT label row. The image
counts and annotation counts are audited independently in
`dataset_inventory.json`; the `wc -l` count can be one smaller for files
without a trailing newline. Exact
open-set scoring uses sidecars generated by
`../scripts/prepare_label_embedding.py`, placed under `../label_spaces/` and
passed to both engines. Without a matching sidecar, the report deliberately
marks a row `unsupported_label_space` instead of comparing different class
spaces. ImageNet and HICO are valid GT sets, but they use dataset-specific
class names (their annotation files store numeric IDs), not the 4,585-class
closed RAM list. The manifest builder decodes those IDs before scoring.

Example for rare OpenImages RAM++:

```bash
python3 cpp_ggml/scripts/prepare_label_embedding.py \
  --model ram_plus --mode open \
  --checkpoint cpp_ggml/models/pytorch/ram_plus_swin_large_14m.pth \
  --tag-list datasets/openimages_rare_200/openimages_rare_200_ram_taglist.txt \
  --descriptions datasets/openimages_rare_200/openimages_rare_200_llm_tag_descriptions.json \
  --output cpp_ggml/benchmarks/label_spaces/openimages_rare_200__ram_plus.f32
```

For ImageNet multi and HICO, RAM uses the official CLIP open-set prompts and
RAM++ uses the deterministic 51-prompt fallback because those datasets do not
ship the RAM++ LLM descriptions:

```bash
python3 cpp_ggml/scripts/prepare_label_embedding.py \
  --model ram --mode open \
  --checkpoint cpp_ggml/models/pytorch/ram_swin_large_14m.pth \
  --tag-list datasets/imagenet_multi/imagenet_multi_1000_taglist.txt \
  --output cpp_ggml/benchmarks/label_spaces/imagenet_multi__ram.f32
python3 cpp_ggml/scripts/prepare_label_embedding.py \
  --model ram_plus --mode open --generic-descriptions \
  --checkpoint cpp_ggml/models/pytorch/ram_plus_swin_large_14m.pth \
  --tag-list datasets/imagenet_multi/imagenet_multi_1000_taglist.txt \
  --output cpp_ggml/benchmarks/label_spaces/imagenet_multi__ram_plus.f32
python3 cpp_ggml/scripts/prepare_label_embedding.py \
  --model ram --mode open \
  --checkpoint cpp_ggml/models/pytorch/ram_swin_large_14m.pth \
  --tag-list datasets/hico/hico_600_taglist.txt \
  --output cpp_ggml/benchmarks/label_spaces/hico__ram.f32
python3 cpp_ggml/scripts/prepare_label_embedding.py \
  --model ram_plus --mode open --generic-descriptions \
  --checkpoint cpp_ggml/models/pytorch/ram_plus_swin_large_14m.pth \
  --tag-list datasets/hico/hico_600_taglist.txt \
  --output cpp_ggml/benchmarks/label_spaces/hico__ram_plus.f32
```

The generic RAM++ sidecar is a reproducible label-space adapter, not the
OpenImages-rare LLM-description protocol; keep those result rows separate in
reports.

For Tag2Text's end-to-end caption path over the retained 50 frames, run
`python3 ../caption_all.py --scope datasets --warmup 1 --repeat 3`.
It uses one resident Python model and one resident GGML model per combination,
and records exact wording plus lexical word F1 separately from tag metrics.

## Visual output audit

Render one image panel per input with the source image, Python reference and
word-level colored differences for every backend/format:

```bash
python3 cpp_ggml/benchmarks/visualize_outputs.py \
  --caption-run cpp_ggml/benchmarks/full_eval/caption-YYYYMMDD-HHMMSS
```

The generated contact sheet is under `cpp_ggml/benchmarks/visualizations/`.
Large run directories, matrices and PNGs are ignored by Git; scripts,
inventory and Markdown methodology remain trackable.
